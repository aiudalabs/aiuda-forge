Por qué no es "otra herramienta de specs"

El artefacto es una commodity. El registro auditable es el producto.

Generar un spec y correr agentes ya existe — pero en una terminal, sin memoria y sin nada que mostrarle a un cliente. No reinventamos eso: lo envolvemos. Lo que una agencia cobra es lo que esas herramientas no dan.

Commodity · una herramienta stateless

Generar specs y correr agentes

  • El artefacto de spec / backlog — se genera y se olvida, sin memoria
  • Un CLI en el IDE de un dev: no es de equipo, hay que estar en la terminal
  • El conocimiento (por qué se decidió X, qué se descartó) se pierde entre sesiones
  • Ningún registro auditable · nada que mostrarle ni firmar a un cliente
El envoltorio que se cobra

Un sistema de registro, no una herramienta

  • Registro auditable y persistente — por proyecto y cliente; guarda lo que se pierde
  • Trail requisito → issue → PR — un entregable auditable que le mostrás al cliente
  • UI de equipo — grafo de dependencias y click-para-despachar, no una terminal
  • Una sola factura, modelos incluidos — sin repartir API keys entre devs
  • Español-first y gates humanos como workflow — donde las tools GitHub-native subatienden
El entregable que factura

Trazabilidad de punta a punta, en un solo hilo.

Cada línea de código llega a un PR; cada PR cierra un Issue; cada Issue nace de un requisito que el cliente aprobó. Ese hilo es lo que adjuntás a la factura.

Para quién es

Agencias y dev shops boutique de LATAM.

  • 1
    3–20 devs que entregan software a la medida a clientes externos de pago, sobre GitHub.
  • 2
    Que necesitan proceso y trazabilidad para ganar y retener la confianza del cliente — no solo escribir código.
  • 3
    Español-first, elicitando requisitos con clientes que hablan español.
  • 4
    Que ya viven en GitHub y quieren specs de calidad + ejecución gobernada sin atarse a un modelo.

No es para

  • El indie hacker / founder no-técnico "idea→app" — usá Lovable, Bolt o v0.
  • El dev solo que solo quiere mejores specs — Spec Kit es gratis en tu IDE.
  • El enterprise con procurement de 9 meses y SSO/SOC2 como requisito de entrada.

Preferimos decirte que no somos para vos hoy, a venderte un asiento que no vas a usar.

Cómo está construido

Casi cero infraestructura. El método es lo único propio.

El sustrato determinista no se escribe: se alquila como config declarativa (Postgres+RLS, GitHub, preview deploys). Lo único propio es el método en markdown + un pegamento fino.
