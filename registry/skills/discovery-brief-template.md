# Skill — discovery-brief-template

Use this template as the structure for the **Project Brief** produced by the Analyst phase.
Fill every section; leave none blank. Short bullets are better than long paragraphs.

---

## Project Brief

### 1. Problem Statement
One to three sentences describing the problem being solved and for whom.

### 2. Vision
The ideal end-state in one sentence: "We will build X so that Y can Z."

### 3. Target Users
- **Primary**: who has the pain today and will use the product daily.
- **Secondary**: adjacent stakeholders who benefit or are affected.

### 4. Core Use Cases (top 3-5)
Numbered list. Each: actor + action + outcome. No implementation detail.
1. …
2. …
3. …

### 5. Out of Scope
Explicitly list what this project does NOT do. Reduces scope creep.

### 6. Constraints & Assumptions
- Technical, budget, time, compliance constraints the solution must respect.
- Assumptions that, if wrong, would invalidate the plan.

### 7. Success Metrics
How we know the project succeeded. At least two: one qualitative, one quantitative.

### 8. Open Questions
Anything still unknown that the PM/Architect must resolve before the PRD is final.

---

**Quality bar**: A reader unfamiliar with the project should understand the full context
after reading the brief. No jargon without definition. No ambiguity in scope.
