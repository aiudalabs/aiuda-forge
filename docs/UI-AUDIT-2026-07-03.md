# UI Audit — consola aiuda-forge post-pivote GitHub-native

**Fecha:** 2026-07-03 · **Método:** navegación real de las 11 secciones con datos de marketpty
(15/44 stories done, SP4/SP9 corriendo vía 4 sesiones GitHub reales).
**Insumos:** PLAN-2026-07-03-pivot-github-native.md (§4 veredictos por vista) + ADR-2026-07-03.

Modelo objetivo: el diseño pasa en Studio; la EJECUCIÓN vive en GitHub (issues, agentes
Copilot/Claude, PRs, checks); el engine es conductor (proyección + dispatch + policy). El
ejecutor factory legacy está apagado por default.

## SOBRA (top 5)

1. **Toda la vista Board · Runs**: lista de runs `factory`/`design` (Cancelled/Failed, $0.00) y botón **"Pause factory"**. Peor: muestra un run fallando con `start docker: executable not found` — un usuario nuevo cree que el producto está roto, cuando la factory está apagada por diseño.
2. **Personas de ejecución + pestaña Workflows en Registry**: `dev`, `python-dev`, `react-dev`, `flutter-dev`, `firebase-dev`, `reviewer`, `verifier` y workflows `factory/factory-plus/gated`. No tienen efecto en la ejecución GitHub. La pestaña **Skills** es config muerta (el propio Docs lo admite: el kernel nunca la carga).
3. **Contenido de Docs**: el tratado kernel/factory/gate entero. Cero valor para el journey nuevo.
4. **Botones `run_bebf25…` y label "workflow: factory · 4 runs"** en las cards Done de Tickets y en el header — referencias a runs legacy junto al PR real.
5. **Métricas legacy-céntricas en Spend/Overview**: "Acceptance % runs→mergeable PR", "Runs DONE 1 of 4", by-step `draft_story/implement`. Miden la fábrica muerta.

---

## FALTA (top 5, priorizado por el journey del usuario nuevo)

1. **Onboarding / conexión GitHub — no existe en NINGÚN lado.** No hay wizard para instalar la GitHub App, elegir org, ni verificar Copilot/plan Claude. El estado vacío (StudioEntry) salta directo a crear un design run asumiendo el `gh` del host. Es el gate #1 de todo el modelo (backlog #1) y está ausente.
2. **Superficie de PRs realmente cableada.** El "PR queue" de Agents está vacío aunque hay PRs; no hay checks/reviews/gate `action_required` ni acciones aprobar-merge según `merge_mode`. Aquí viven ahora los gates humanos — el hueco más grande post-Studio.
3. **Live-view de sesiones de agente.** `session ↗` linkea al workflow genérico `claude.yml` (el MISMO URL para las 4 sesiones), no al run específico. El buen LiveLog/TimelineBar/event-stream sigue atrapado en runs muertos de Board en vez de proyectar la sesión GitHub real.
4. **El handoff "Publicar a GitHub" como cierre del diseño.** Tickets tiene "Export to GitHub" (issues+deps) pero falta el scaffold completo: repo base + especialización (`.github/agents/`, `AGENTS.md`, workflows QA) como la acción de "diseño aprobado → ejecución".
5. **Controles de dispatch/aprobación en el trabajo listo.** Settings promete un "▶ Dispatch button on ready stories/sprints" y "Approve and run workflows" por PR en modo approve; en Tickets las stories Ready muestran solo una pill `▶ SP5` sin acción de despacho clara, y no hay superficie para el workflow-approval por PR.

Bonus transversal: **rebranding**. El wordmark "Factory", el título de pestaña "Aiuda Factory" y copys como "How the factory groups work into PRs" siguen llamando fábrica a un producto que ya no lo es.

## 3 quick-wins (< 1h c/u)

1. **Sacar Board · Runs del nav** (redirigir `/board` → `/agents`) y borrar el botón "Pause factory". Su fila de KPIs (Running/Awaiting/Open PRs/Cost) se mueve a Agents u Overview. Elimina de un golpe la vista que hace parecer roto al producto (error docker) y la duplicación Board/Agents.
2. **Filtrar Registry a solo personas de diseño** (colapsar ejecución + Workflows tras "avanzado/legacy") y quitar la pestaña Skills muerta. Así editar en Registry deja de implicar falsamente que afecta a los agentes GitHub.
3. **Limpiar las cards Done de Tickets**: quitar los botones `run_…` y el label "workflow: factory · N runs", dejando solo el `PR ↗` real. Cambio de mapeo en `api.ts`/render del ticket; alinea la vista canónica con el modelo nuevo sin tocar backend.

Cuarto si hay tiempo: el conteo de PRs no cuadra entre superficies (Board "Open PRs: 1", Agents "No open PRs", Tickets 4 PRs enlazados). Unificar la fuente antes de construir la PR-view definitiva.
